# FR-AUT-002: Menu tùy chỉnh

| Mục | Nội dung |
| --- | --- |
| Mô tả | Quản lý nhiều menu thay thế và gán một menu riêng cho từng khách.<br>**Phạm vi và dữ liệu:** Bao gồm CRUD, nhân bản, draft/publish, item, preview, gán/gỡ menu cho khách, click và xử lý xóa. Không sửa Menu mặc định, không tự phân khúc theo nhãn/User Field, không định nghĩa action đích. Sở hữu `CustomMenu {id, channelId, name, versions, status, items[]}` và `CustomerMenuAssignment {customerId, channelId, menuId, assignedAt, source, correlationId}`. Mỗi khách có tối đa một assignment hiệu lực trên một kênh. |
| Đối tượng liên quan | Admin/Quản lý; Rule/Flow/API gọi command; khách hàng. |
| Pre-conditions | Kênh hỗ trợ menu; Menu mặc định tồn tại; target action thuộc cùng kênh. |
| Điều kiện kích hoạt | Quản trị mở Automation → Menu tùy chỉnh; hoặc Rule/Flow/API gửi command gán/gỡ menu cho khách; hoặc khách bấm item menu tùy chỉnh. |
| Luồng xử lý chính | 1. Danh sách hiển thị tên, trạng thái, số khách đang gán, lần cập nhật và thao tác Tạo/Sửa/Đổi tên/Nhân bản/Xóa.<br>2. Tạo menu yêu cầu tên duy nhất trong kênh, sau đó dùng cùng contract item/capability như FR-001.<br>3. Lưu nháp và publish theo vòng đời chung. Menu chỉ được gán khi có published version hợp lệ.<br>4. `assignMenu(customerId, menuId)` kiểm tra cùng tenant/kênh và menu đã publish, sau đó upsert assignment, audit và phát `customer_menu.assigned`.<br>5. `unassignMenu(customerId)` xóa assignment; resolver lập tức quay về FR-001 và phát `customer_menu.unassigned`.<br>6. Nhân bản sao chép draft/item sang ID mới, trạng thái nháp; không sao chép assignment, analytics hoặc publish history.<br>7. Xóa hiển thị số assignment và tham chiếu. Sau xác nhận, transaction gỡ assignment, hủy menu và đánh dấu consumer cần cấu hình lại. |
| Post-condition | Catalog và assignment được cập nhật; resolver trả menu riêng hoặc fallback FR-001. |
| Luồng thay thế | - Tên trống/trùng sau trim và không phân biệt hoa thường: chặn lưu.<br>- Gán menu nháp, sai kênh hoặc bị archive: từ chối, giữ assignment cũ.<br>- Menu đích mất hiệu lực tại runtime: gỡ assignment an toàn, ghi log và fallback FR-001.<br>- Xóa có tham chiếu từ Rule/Sequence: phải cảnh báo; consumer chuyển `NEEDS_RECONFIGURATION`. |
| Sub-flow | **SF-01 – Gán menu:** atomic upsert, mỗi customer/channel tối đa một assignment.<br>**SF-02 – Gỡ/xóa menu:** gỡ assignment và fallback FR-001; consumer tham chiếu menu bị xóa chuyển `NEEDS_RECONFIGURATION`.<br>**SF-03 – Nhân bản:** sao chép item sang ID nháp mới, không sao chép assignment, analytics hay publish history. |
| Giao diện hệ thống | Màn danh sách Menu tùy chỉnh gồm tìm kiếm, trạng thái, số khách được gán và menu thao tác; editor item/preview dùng cùng contract menu; dialog tạo, đổi tên, nhân bản, xóa và xem impact. |
| Yêu cầu phi chức năng | Resolver menu p95 ≤ 100 ms từ cache; assignment nhất quán đọc-sau-ghi; thao tác xóa lớn chạy job có tiến độ, retry và báo cáo kết quả. |
| AC tương ứng | - **AC-AUT-002-01:** Tạo tên hợp lệ sinh menu nháp; tên trùng bị chặn.<br>- **AC-AUT-002-02:** Nhân bản sinh ID mới, đủ item, không có assignment/số liệu.<br>- **AC-AUT-002-03:** Gán menu published cho khách làm resolver trả menu đó; gỡ gán trả Menu mặc định.<br>- **AC-AUT-002-04:** Gán menu sai kênh/nháp bị từ chối và không làm mất assignment cũ.<br>- **AC-AUT-002-05:** Xóa menu có N khách hiển thị N; sau xác nhận không còn assignment mồ côi.<br>- **AC-AUT-002-06:** Hai command gán cùng `requestId` chỉ tạo một thay đổi/audit event. |
| BR tương ứng | - **BR-AUT-002-01:** Tên menu duy nhất trong kênh sau trim/case-fold.<br>- **BR-AUT-002-02:** Chỉ menu published cùng kênh được gán.<br>- **BR-AUT-002-03:** Mỗi khách/kênh chỉ có một assignment; lệnh gán mới thay thế assignment cũ theo atomic upsert.<br>- **BR-AUT-002-04:** Xóa menu phải gỡ toàn bộ assignment; khách fallback về FR-001.<br>- **BR-AUT-002-05:** Tạo menu không tự gán cho bất kỳ khách nào. |
