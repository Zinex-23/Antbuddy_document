# FR-AUT-009: Tự động cập nhật User Field

| Mục | Nội dung |
| --- | --- |
| Mô tả | Tự động ánh xạ, biến đổi, validate và ghi giá trị vào User Field từ event, biểu thức, giá trị hằng hoặc nguồn tích hợp được cho phép. FR sở hữu `FieldUpdateJob`, mapping, transformation, conflict policy và execution result. Schema/danh mục User Field do CRM/Profile service sở hữu; Rule chỉ quyết định khi gọi job; FR-010 chỉ thu câu trả lời.<br>**Phạm vi:** Bao gồm: danh sách job; tạo/sửa/nhân bản/xóa/bật-tắt; chọn nguồn; mapping nhiều field; transform; validate; preview trên dữ liệu mẫu; conflict policy; update atomic hoặc best-effort; retry; log; command cập nhật một field dùng chung.<br>Không bao gồm: tạo schema User Field; form hỏi khách; xác định trigger/condition của Rule; import CRM tổng quát; enrichment không có nguồn/consent hợp lệ. |
| Đối tượng liên quan | Admin/Quản lý; Rule/Sequence/Form/API; Customer Profile service |
| Pre-conditions | Người dùng có quyền; schema User Field đích đang hoạt động; nguồn dữ liệu/credential/consent hợp lệ; Profile service khả dụng. |
| Điều kiện kích hoạt | Command từ consumer; event đã cấu hình; lịch; webhook tích hợp |
| Luồng xử lý chính | 1. Chọn phạm vi kênh, nguồn (`EVENT_PAYLOAD`, `CONSTANT`, `EXPRESSION`, `INTEGRATION_RESPONSE`, `CAPTURED_ANSWER`) và schema nguồn.<br>2. Thêm mapping: `sourcePath/expression → targetFieldId`; có thể nối pipeline `trim`, chuẩn hóa số/email, parse number/date, map enum, concat, default value. Không cho phép code tùy ý.<br>3. Chọn khi giá trị nguồn rỗng: `SKIP`, `CLEAR` hoặc `USE_DEFAULT`; `CLEAR` cần quyền và xác nhận rõ.<br>4. Chọn conflict policy: `OVERWRITE`, `ONLY_IF_EMPTY`, `KEEP_NEWER` hoặc `REJECT_IF_CHANGED`. Chính sách áp dụng theo từng mapping.<br>5. Chọn transaction policy: `ALL_OR_NOTHING` hoặc `BEST_EFFORT`. Mặc định `ALL_OR_NOTHING` cho command từ Form; job bulk có thể dùng `BEST_EFFORT`.<br>6. Preview hiển thị input đã che dữ liệu nhạy cảm, giá trị sau transform, validation và quyết định ghi; không ghi thật.<br>7. Chỉ cho bật khi schema, mapping, credential, consent/purpose (nếu cần) và policy đều hợp lệ.<br>**Runtime:** 1. Nhận command/event; xác thực tenant, kênh, customer, source và idempotency key.<br>2. Tải version job và schema field; chụp current values/version để đánh giá conflict.<br>3. Trích xuất → transform → validate kiểu/range/enum → áp dụng empty/conflict policy.<br>4. Ghi qua API Profile service, không ghi database CRM trực tiếp. `ALL_OR_NOTHING` ghi transaction; `BEST_EFFORT` trả kết quả từng field.<br>5. Lưu old/new value đã mask hoặc hash theo phân loại dữ liệu, actor/source, version và result.<br>6. Sau commit phát `user_field.updated` cho từng field thực sự thay đổi; không phát nếu giá trị không đổi. |
| Post-condition | Các field hợp lệ được ghi theo transaction/conflict policy; kết quả từng field được lưu và event chỉ phát sau commit. |
| Luồng thay thế | - Schema đích bị xóa/đổi kiểu: tự tắt job và `NEEDS_RECONFIGURATION`.<br>- Input thiếu/sai kiểu: xử lý theo policy; không ép kiểu mập mờ.<br>- Conflict: `ONLY_IF_EMPTY`/`KEEP_NEWER` trả `SKIPPED_CONFLICT`; `REJECT_IF_CHANGED` thất bại có thể retry sau khi đọc lại.<br>- Integration timeout: không retry ghi cho tới khi xác định kết quả bằng idempotency key.<br>- Job bulk: mỗi customer có execution riêng; lỗi một customer không làm rollback customer đã thành công. |
| Sub-flow | **SF-01 – Transform:** trim, chuẩn hóa, parse, map enum, concat và default; không chạy code tùy ý.<br>**SF-02 – Empty policy:** `SKIP`, `CLEAR`, `USE_DEFAULT`.<br>**SF-03 – Conflict:** `OVERWRITE`, `ONLY_IF_EMPTY`, `KEEP_NEWER`, `REJECT_IF_CHANGED`.<br>**SF-04 – Transaction:** `ALL_OR_NOTHING` hoặc `BEST_EFFORT`; PII được mask theo quyền. |
| Giao diện hệ thống | Màn danh sách job; editor source/mapping/transform/empty/conflict/transaction policy; preview dữ liệu đã mask; execution log theo customer/field; trạng thái credential/schema. |
| Yêu cầu phi chức năng | Command một customer p95 ≤ 500 ms không tính integration ngoài; batch có throttling/checkpoint/resume; encryption in transit/at rest; secret chỉ qua secret manager; retention và right-to-erasure tuân theo phân loại field; dashboard có success/skip/failure/retry/DLQ. |
| AC tương ứng | - **AC-AUT-009-01:** Mapping hợp lệ chuyển đổi và ghi đúng kiểu field; preview cho cùng kết quả như runtime nhưng không ghi.<br>- **AC-AUT-009-02:** `ONLY_IF_EMPTY` không ghi đè field đã có và trả đúng skip reason.<br>- **AC-AUT-009-03:** `ALL_OR_NOTHING` có một mapping sai thì không field nào thay đổi.<br>- **AC-AUT-009-04:** `BEST_EFFORT` ghi các mapping hợp lệ và báo lỗi riêng mapping sai.<br>- **AC-AUT-009-05:** Command giao lặp không tạo update/event thứ hai.<br>- **AC-AUT-009-06:** Field đích đổi schema làm job tự tắt và chỉ rõ mapping lỗi.<br>- **AC-AUT-009-07:** Cập nhật thành công từ FR-010 mang đúng `captureSessionId` trong correlation chain. |
| BR tương ứng | - **BR-AUT-009-01:** Mỗi mapping phải trỏ tới field active và giá trị cuối phải đúng schema.<br>- **BR-AUT-009-02:** `null`, chuỗi rỗng và thiếu path là ba trạng thái phân biệt; xử lý theo empty policy.<br>- **BR-AUT-009-03:** Cùng idempotency key + customer + job version chỉ ghi một lần.<br>- **BR-AUT-009-04:** Chỉ phát `user_field.updated` sau commit và khi old value khác new value.<br>- **BR-AUT-009-05:** Transform không được thực thi code tùy ý hoặc truy cập dữ liệu ngoài tenant.<br>- **BR-AUT-009-06:** PII được mask trong UI/log/export theo quyền và chính sách lưu trữ. |
