# FR-AUT-007: Quản lý thẻ nhãn khách hàng (Customer Tagging)

| Mục | Nội dung |
|---|---|
| **Mô tả** | Cho phép Admin tạo và quản lý **thẻ nhãn (tag)** để phân loại khách hàng trong quá trình hội thoại:<br>- Bot có thể tự động **gắn tag** cho khách khi khách bấm nút, gõ từ khóa, hoặc khi Quy luật tự động kích hoạt.<br>- Admin cũng có thể gắn/gỡ tag thủ công trực tiếp trên hồ sơ khách.<br>- Tag được dùng để **lọc khách** trong Gửi tin hàng loạt (FR-013) và **làm điều kiện** trong Quy luật (FR-009) và Kịch bản chăm sóc (FR-008).<br>- **Ví dụ thực tế**: Khách bấm "Quan tâm sản phẩm A" ➔ Hệ thống tự gắn tag `Quan_tam_SP_A` ➔ Sau 3 ngày Kịch bản nuôi dưỡng tự gửi ưu đãi sản phẩm A cho tất cả khách có tag đó. |
| **Đối tượng liên quan** | Admin, Quản lý, Bot (tự động gắn tag khi chạy Flow/Quy luật) |
| **Pre-conditions** | Người dùng đã đăng nhập và có quyền quản lý Automation. |
| **Điều kiện kích hoạt** | - Admin vào mục "Quản lý nhãn" để xem/tạo/xóa tag.<br>- Bot tự gắn tag khi chạy hành động "Gắn nhãn" trong Flow, Kịch bản hoặc Quy luật.<br>- Admin gắn/gỡ tag thủ công từ hồ sơ khách hàng. |
| **Luồng xử lý chính** | **1. Tạo tag mới**: Vào "Quản lý nhãn" ➔ Bấm "Tạo nhãn" ➔ Nhập tên tag (ví dụ: `Khach_VIP`, `Da_Mua_Hang`, `Can_Cham_Soc`) ➔ Chọn màu sắc để phân biệt ➔ Lưu.<br>**2. Gắn tag tự động (trong Flow/Quy luật)**: Khi soạn hành động trong Flow, chọn "Gắn nhãn" ➔ Chọn tag từ danh sách ➔ Lưu. Khi Flow chạy đến bước đó, hệ thống tự gắn tag vào hồ sơ khách.<br>**3. Gắn tag thủ công**: Mở hồ sơ khách hàng ➔ Khu vực "Nhãn" ➔ Gõ hoặc chọn từ danh sách ➔ Bấm Lưu.<br>**4. Gỡ tag**: Bấm nút X trên tag trong hồ sơ khách, hoặc dùng hành động "Gỡ nhãn" trong Flow/Quy luật.<br>**5. Lọc theo tag**: Trong Gửi tin hàng loạt, chọn "Lọc theo nhãn" ➔ Hệ thống đếm số khách có tag đó ➔ Xác nhận gửi. |
| **Post-condition** | Tag được lưu trong hồ sơ khách. Mọi chức năng khác (Broadcast, Kịch bản, Quy luật) có thể dùng tag này làm bộ lọc hoặc điều kiện ngay lập tức. |
| **Luồng thay thế** | - **AF-1 (Tên tag trùng)**: Hệ thống thông báo "Nhãn đã tồn tại" và không tạo tag mới; đề xuất dùng tag cũ.<br>- **AF-2 (Xóa tag đang được dùng)**: Hệ thống cảnh báo "Nhãn này đang được dùng trong N luồng/quy luật/kịch bản. Xóa sẽ gỡ tag khỏi tất cả khách hàng. Tiếp tục?". Yêu cầu xác nhận trước khi xóa.<br>- **AF-3 (Gắn tag không tồn tại từ API)**: Hệ thống tự tạo tag mới với tên đó thay vì báo lỗi (để hỗ trợ tích hợp API bên ngoài). |
| **Sub-flow** | - **SF-01 (Hành động "Gỡ nhãn")**: Ngoài "Gắn nhãn", Flow và Quy luật cũng hỗ trợ hành động "Gỡ nhãn" để xóa tag khỏi khách (ví dụ: sau khi khách mua hàng, tự gỡ tag `Can_Cham_Soc` và gắn tag `Da_Mua_Hang`). |
| **Giao diện hệ thống** | - **Màn hình "Quản lý nhãn"**: Bảng danh sách tag gồm tên, màu sắc, số khách đang có tag đó, ngày tạo, nút xóa.<br>- **Trên hồ sơ khách**: Khu vực "Nhãn" hiển thị dạng pill/chip màu sắc, có nút thêm và nút X để gỡ từng tag.<br>- **Trong Flow/Quy luật**: Khi chọn hành động "Gắn nhãn" hoặc "Gỡ nhãn", hiển thị ô tìm kiếm + danh sách tag có sẵn để chọn. |
| **Yêu cầu phi chức năng** | - Gắn/gỡ tag bởi bot trong ≤ 500ms.<br>- Bộ lọc theo tag trong Broadcast phải đếm chính xác số khách (không được tính khách trùng).<br>- Tối đa 50 tag cho mỗi khách hàng. |
| **AC tương ứng** | - **AC-01**: Admin tạo tag `Khach_VIP` ➔ Tag xuất hiện trong danh sách chọn của Broadcast và Quy luật.<br>- **AC-02**: Flow chạy đến bước "Gắn nhãn: Da_Mua_Hang" ➔ Mở hồ sơ khách hàng đó ➔ Thấy tag `Da_Mua_Hang` đã được gắn.<br>- **AC-03**: Vào Broadcast, lọc theo tag `Da_Mua_Hang` ➔ Hệ thống hiển thị đúng số lượng khách hàng có tag đó.<br>- **AC-04**: Xóa tag đang có 50 khách ➔ Hệ thống hiển thị cảnh báo và yêu cầu xác nhận trước khi xóa. |
| **BR tương ứng** | - **BR-01**: Tên tag không được để trống, không được có ký tự đặc biệt ngoài dấu gạch dưới `_` và dấu gạch ngang `-`.<br>- **BR-02**: Mỗi khách hàng tối đa 50 tag.<br>- **BR-03**: Xóa tag không xóa lịch sử sử dụng tag đó (phục vụ báo cáo hồi tố). |
