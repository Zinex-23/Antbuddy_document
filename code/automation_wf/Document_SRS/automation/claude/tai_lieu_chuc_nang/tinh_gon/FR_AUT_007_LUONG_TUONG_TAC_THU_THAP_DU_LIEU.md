# FR-AUT-007: Luồng Hội thoại Tương tác & Thu thập Dữ liệu (Bản tinh gọn)

| Mục | Nội dung |
|---|---|
| **Mô tả** | Bộ máy kịch bản hội thoại phân nhánh động (Flow Builder) và thu thập thông tin khách hàng:<br>- **Rẽ nhánh thông minh**: Điều hướng hội thoại theo lựa chọn của khách (Nút A ➔ Nhánh 1; Nút B ➔ Nhánh 2).<br>- **Thu thập dữ liệu (User Input)**: Bot đặt câu hỏi và đợi khách trả lời; tự động kiểm tra định dạng (Validate: Số điện thoại, Email, Số, Ngày tháng, Văn bản tự do).<br>- **Lưu vào CRM**: Tự động trích xuất câu trả lời lưu vào Trường dữ liệu khách hàng (Custom Fields).<br>- **Xử lý nhập sai**: Nhập sai định dạng ➔ Nhắc lại tối đa 3 lần ➔ Nếu vẫn sai thì chuyển về nhân viên hỗ trợ. |
| **Đối tượng liên quan** | Admin, Quản lý |
| **Pre-conditions** | Đã đăng nhập; Trang đang kết nối và hoạt động. |
| **Điều kiện kích hoạt** | Khách bấm nút hoặc được định tuyến kích hoạt một Luồng tin nhắn (`FLOW`). |
| **Luồng xử lý chính** | **1. Soạn luồng**: Thêm các node tin nhắn, node rẽ nhánh, node hỏi đáp thu thập thông tin.<br>**2. Cấu hình thu thập**: Chọn loại dữ liệu cần hỏi (ví dụ: SĐT) ➔ Gán trường lưu (`customer.phone`) ➔ Soạn câu nhắc khi nhập sai.<br>**3. Runtime khi chạy luồng**: Bot gửi câu hỏi ➔ Khách trả lời ➔ Hệ thống validate dữ liệu ➔ Đúng định dạng thì lưu vào CRM và chuyển sang bước tiếp theo của luồng. |
| **Post-condition** | Dữ liệu khách hàng được điền tự động vào CRM; tiến trình hội thoại đi đúng nhánh kịch bản. |
| **Luồng thay thế** | - **AF-1 (Khách nhập sai)**: Khách nhập chữ khi bot hỏi SĐT ➔ Bot gửi câu nhắc: "Số điện thoại không hợp lệ, vui lòng nhập lại".<br>- **AF-2 (Quá 3 lần nhập sai)**: Khách nhập sai 3 lần liên tiếp ➔ Gắn thẻ `Can_Ho_Tro`, chuyển cuộc trò chuyện sang hàng đợi nhân viên.<br>- **AF-3 (Khách im lặng / Bỏ dở luồng)**: Khách không trả lời sau 24 giờ ➔ Hết hạn phiên nhập dữ liệu (Timeout), giải phóng trạng thái chờ. |
| **Sub-flow** | - **SF-01 (Bộ kiểm tra định dạng Validator)**: Hỗ trợ Regex SĐT Việt Nam, Regex Email RFC 5322, kiểm tra số nguyên/thực, kiểm tra ngày tháng DD/MM/YYYY.<br>- **SF-02 (Cập nhật CRM)**: Sau khi validate thành công, gọi API cập nhật ngay lập tức vào bảng `customers`. |
| **Giao diện hệ thống** | - **Màn hình Flow Canvas**: Giao diện sơ đồ kéo thả các node (Tin nhắn, Rẽ nhánh, Thu thập dữ liệu, Hành động).<br>- **Node Cấu hình Thu thập dữ liệu**: Chọn trường dữ liệu cần lưu, chọn kiểu kiểm tra (Phone/Email/Number), câu hỏi, câu báo lỗi khi nhập sai. |
| **Yêu cầu phi chức năng** | - Kiểm tra định dạng dữ liệu hoàn tất trong < 50ms.<br>- Hỗ trợ luồng rẽ nhánh tối đa 30 node liên kết. |
| **AC tương ứng** | - **AC-01**: Khách nhập "0912345678" ➔ Hệ thống lưu thành công vào trường SĐT của khách và chuyển bước kế.<br>- **AC-02**: Khách nhập chữ "abc" khi bot hỏi email ➔ Bot báo lỗi và yêu cầu nhập lại, không lưu "abc".<br>- **AC-03**: Khách bấm nút chọn "Tư vấn gói VIP" ➔ Luồng rẽ chính xác sang nhánh VIP.<br>- **AC-04**: Khách nhập sai 3 lần liên tục ➔ Luồng dừng và chuyển cuộc trò chuyện cho nhân viên. |
| **BR tương ứng** | - **BR-01**: Một node thu thập dữ liệu chỉ được gán lưu vào đúng 1 trường thuộc tính khách hàng.<br>- **BR-02**: Giới hạn tối đa nhắc lại khi nhập sai là 3 lần.<br>- **BR-03**: Khi khách đang trong trạng thái chờ nhập dữ liệu của Flow, các bộ lọc Từ khóa thông thường tạm thời bị khóa cho đến khi hoàn tất hoặc timeout. |
